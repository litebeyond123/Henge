# Henge 0.4 Test 11（4012）——修复退出检查提前停止，自动保存网络包头

4011 的实机报告中，一轮已确认原 ChatGPT 主进程退出，随后在启动前检查时发现新的主进程；另两轮停在 `NSPOSIXErrorDomain / 3` 的进程查询错误，没有等到原有退出期限。保留的这几轮都没有记录适配器启动或加载，Henge 认证桥也没有收到 token、BAA 或能力探测请求。

**本版修复已定位的退出等待缺口，同时把进程检查和限时抓包放进同一份诊断报告。** 它不代表原生 Chat 已恢复，也不能把启动器的 POSIX 错误解释为 Apple 认证服务返回的错误。

## 本次修复

- Mac 助手升级为 **11**，认证启动能力为 **4**，健康协议仍为 **4**。正常退出和强制退出都要求当前 VM 回连的 Helper 11；旧助手读取认证状态时不能领取新请求。
- 发出一次实际退出操作后，如果内核仍能核对同一 PID、启动时间和用户身份，但 `proc_pidpath` 暂时返回 `ESRCH`，继续使用本次操作剩余的退出等待时间。正常退出仍最多 **30 秒**，明确选择的强制退出仍最多 **10 秒**，不另外重置期限。
- 路径暂时不可用仍是“身份信息不完整”，不会直接当成已退出或仍存活。只有后续明确观察到原进程不存在或已进入僵尸状态，才继续启动流程。其他查询错误、PID 身份替换、授权撤销均停止。
- 每轮最多调用一次退出操作。正常退出不会自动强退，发现新实例也不会循环结束它。原应用和适配器的完整签名验证保留。
- 增加实际退出方法是否调用、返回结果、查询来源、身份标志、重采样次数、采样耗时，以及退出后的签名检查和进程枚举耗时。所有字段均为固定枚举或数字。
- 每个被接受的启动阶段立即写入持久原生日志。即使多次尝试挤掉了 32 条近期事件缓存，已落盘的较早阶段仍可在同一报告中分析。

## 自动抓包

每次成功开始认证测试，自动在虚拟网卡处记录 **120 秒或 2 MiB** 的真实网络包头，先到上限即停止。停止测试、Henge 进入后台或 VM 结束也会停止捕获并保留已记录的数据。

- 记录实际发送的帧和成功交付给 VM 的接收帧；接收缓冲区不足另计，不伪装成已交付。
- 动态解析以太网、VLAN、IP、TCP/UDP 的边界，仅保留确认后的协议头，排除 HTTP 正文、令牌、Cookie 和其他应用载荷。畸形或不支持的包另有计数。
- 可分析目的 IP/端口、连接方向、TCP 序号/标志、连接复位、重传迹象和原始包长；**不能从此文件读取 HTTPS 正文、HTTP 状态码或 DNS 查询名称**。
- 捕获范围是整台虚拟 Mac 的网卡，不能仅凭端口就把所有流量归给 ChatGPT。iPad 上 DeviceCheck/BAA 原生框架的外网请求不经过该网卡；其结果仍看独立认证回执。
- 一次新测试替换当前内存中的捕获。每次诊断快照将当前捕获、所属会话/启动 UUID、停止原因和 SHA-256 一并保存。没有捕获时明确写为 `not_started`，不会把旧文件拼成当前数据。

PCAP 以 Base64 嵌入 **同一份 `Latest-Henge-diagnostics.txt`**，另有独立副本 `HengeDiagnostics/Inputs/Network/Latest-Henge-network-headers.pcap`。继续只发 TXT 即可，不需要自行安装抓包工具或区分多种日志。数据不会自动上传。

## Mac 日志采集

手动导出时，Mac 日志查询预算改为最多 **30 秒**，总采集预算最多 **35 秒**，iPad 异步等待最多 **45 秒**；仍受诊断请求剩余寿命限制。自动采集保留原有较短预算及资源保护。超时前完整取得的事件保留为部分证据；没有取得事件时明确标记不可用，零计数不代表无错误。

诊断采集不再重复执行耗时的完整签名验证，报告如实写为未执行；认证启动器自己的签名检查不变。新增从固定 Electron Framework 元数据中读取版本号，为后续判断客户端网络日志能力提供依据；本版没有开启或导出原始 NetLog。

## 这次怎么测试

1. 保存 Mac 内的工作并正常关机，用 TrollStore 覆盖安装 **0.4 Test 11 / 4012**，保留 Henge 数据和现有 Mac。
2. 启动原来的 Mac，在终端聚焦输入行并使用 ABC / U.S. 输入布局。到 **ⓘ → Details → Sharing** 点 **Type Install / Repair Command**，命令输入完整后回终端按回车。等到显示 **Mac helper 11 · Connected**。
3. 到 **ChatGPT authentication · Test11**，先保留 **iPad DeviceCheck token** 路径，只做一轮。保存 ChatGPT 未发送的输入后，可选 **Force quit ChatGPT and retry**；它可能丢失该应用未保存的内容。无需先靠关闭窗口来模拟退出。
4. 保持 Henge 前台，等待实际阶段。如果显示 **Adapter ready**，在 Mac 的 Chat 中发送一次测试消息。若直接失败，保留该次结果。抓包最多持续两分钟。
5. 仍有错误时使用导出诊断，等待采集完成，提供 **文件 → 我的 iPad → Henge → HengeDiagnostics → Latest-Henge-diagnostics.txt**。同一文件含实际启动阶段、认证回执、Mac 分类日志和网络包头。先导出这一轮，再切换模式，便于保留对应捕获。

无需重建虚拟机。只升级 iPad 端而仍运行 Helper 10，不会使用这次退出等待修复。

## 验证与边界

发布流程包含实际 macOS 自有应用的退出/重启/适配器握手测试、共用生产退出状态机的长于 250 ms 过渡和期限测试、PCAP 独立解码及载荷排除检查、真实延迟子进程日志采集、HTTP 和状态 schema、Foundation 报告编码、助手安装回连、iOS 编译、签名与包校验。

合成认证测试不使用真实 Apple 账号，也不证明 OpenAI 服务端接受。`DCDevice.isSupported`、Apple 返回令牌、客户端实际接入和服务端接受是不同结果。最终是否修复原生 Chat，仍需这台 iPad 的现有 VM 中实际发送消息并收到回复确认。
