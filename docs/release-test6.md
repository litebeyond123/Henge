# Henge 0.4 Test 6（4007）

本版修复 Mac 助手已连接、但 Chat 错误摘要仍因采集预算耗尽而不可用的问题。保留 Test 5 的助手应用与连接方式，更新现有 Henge 和 Mac 助手即可使用原来的 Mac、磁盘与账户。

## 本次修复

- **关键日志优先。** 不再让多个系统信息命令及签名检查先消耗日志查询的时间。基础系统信息改用本地 API 读取，日志查询获得约 8 秒独立预算，签名信息和签名验证放在后面，各自受短预算约束。采集仍有总预算，不延长为持续后台扫描。
- **超时保留已有证据。** 使用逐行 JSON 读取系统日志；已经完整解析的错误会保留。超时、输出达到上限、子进程失败或不完整 JSON 行均有明确状态，不再因最终查询未完成就丢弃此前全部有效事件。
- **计数标明可用程度。** 摘要区分完整、部分和未取得。部分计数只代表已经读到的事件；未取得时的兼容字段零值不能说明没有错误。查询完整但没有识别出错误，也不说明 Chat 已可用。
- **补全过滤条件。** 包含 `DCDevice supported=false` 这类已由分类器支持、此前可能在查询前被漏掉的消息；客户端进程与子系统也参考已安装 ChatGPT.app 的受限元数据。
- **每次结果都留记录。** 统一报告保存每个被接受请求的固定结果分类、来源计数和耗时。之后某次摘要不完整时，较早观察到的错误仍可从同次运行日志中追溯，不需要单独寻找 Mac 日志。
- **分阶段报告耗时。** 区分日志命令是否真正启动、执行状态和退出信息，以及元数据、签名显示、签名验证阶段，便于确定卡在哪里。

这些改动修复的是诊断漏采。它们不产生 DeviceCheck 令牌，也不改变原生 Chat 的设备认证要求。系统 DeviceCheck 服务的错误和客户端自身错误仍分开计数，不能直接将前者归因于客户端请求。本版没有改变虚拟机磁盘格式或图形设备实现。

## 更新与测试

1. 保存 Mac 中的工作并正常关机，用 TrollStore **覆盖更新到 0.4 Test 6 / 4007**。保留 Henge 的数据，不需要重建 Mac。
2. 启动原来的 Mac，在 Mac“终端”中使用 ABC / U.S. 键盘布局并点入输入区。到 Henge 顶部 **ⓘ → Details → Sharing → Type Install / Repair Command**，等命令输入完成后回到终端按一次回车。**本次需更新一次 Mac 助手到版本 6**，仅更新 iPad 上的 Henge 无法替换 Mac 内已安装的采集器。
3. 等待 **Connected / Installation confirmed**。若 macOS 要求本地网络访问，请允许；保持助手运行，不必在每次打开 Details 时重复安装。
4. 在 Mac 中复现一次 Chat 问题，然后从运行中的顶部详情点击 **Collect Chat diagnostics**。发送生成的同一份报告即可，不需要区分或挑选日志文件。

报告会自动保存在 **文件 → 我的 iPad → Henge → HengeDiagnostics → Latest-Henge-diagnostics.txt**。导出不要求关闭 Mac。诊断不自动上传，不读取对话数据库、Cookie、令牌或钥匙串，也不保存系统日志原文。

## 发布验证范围

构建门槛包含超时前有效事件保留、残缺及过长行处理、子进程退出状态、来源分类、主机字段校验、旧摘要兼容和安装回归检查。新增的 macOS 验证向系统日志写入一条独立随机类别的合成错误，经真实 `log show --style ndjson` 和生产分类器读回；它不会读取并发布其他运行日志。

现有签名助手启动、实际健康连接、TIPA 构建、签名与内容检查继续执行。构建机测试不能替代 iPad 上的长时间运行验证，也不证明虚拟 macOS 能生成服务端认可的设备认证令牌。
