# Henge 0.4 Test 10（4011）——确认实际进程退出，再启动认证实验

4010 实机报告已经确认 Helper 9 正常连接，六次启动授权均被接受。但保留的后三次尝试仍停在退出 ChatGPT：两次正常退出等待约 8 秒后超时，另一次先记录退出完成，随后又发现匹配的运行进程。报告没有目标进程的身份对照，不能判断后者是新实例还是应用状态缓存的差异。三次都没有进入适配器启动，也没有向 iPad 请求 token 或 BAA 签名。

**本版修复这段冷启动流程：正常退出最多等待 30 秒，以内核进程身份确认退出，并增加用户明确选择的强制退出重试。** 更新原来的 Henge 和 Mac 助手即可继续使用已有虚拟机。

这不是原生 Chat 已恢复的声明。安装后还需要确认官方客户端是否实际加载适配器、Apple 调用是否完成，以及 Chat 服务端是否接受结果。界面和自动报告会分别记录这些阶段。

## 本次改变

- Mac 助手升级到 **10**，认证启动能力为 **3**，健康协议仍为 **4**。新版界面核对实际回连的助手，旧助手不能领取强制退出请求。
- 正常退出等待从约 **8 秒**增加到 **30 秒**，同时调整启动前和整个启动流程的时间预算，避免增加退出等待后又撞上旧的总超时。
- 使用目标主进程的 **PID、内核启动时间、用户身份和规范化可执行路径**核对同一实例。应用状态对象不再单独决定进程是否已经退出；PID 相同也不代表仍是原进程。
- 新增 **Force quit ChatGPT and retry**。这是一次独立、明确的操作；可能丢失 ChatGPT 中尚未发送的输入。它只请求退出本次核验的原 ChatGPT 主进程，然后等待实际结束。正常退出不会自动升级为强制退出。
- 退出过程中若发现进程身份变化或另一个匹配实例出现，就停止该次启动，不循环结束新实例。无法核对身份时同样停止。
- 每次启动将所选模式和退出方式绑定到同一个请求。切换方式需要新请求；助手重启或重复轮询不能把同一请求执行第二遍。
- 报告记录普通退出与强制退出的不同阶段，并保存原目标 PID 和后续观察到的 PID，帮助解释“已退出后又发现进程”，不再要求用户通过启动速度猜测是否冷启动。
- 保留目标应用及适配器的完整签名检查、前台授权检查、实际加载和成功握手的区分。强制退出请求不改变 macOS 是否允许加载适配器的决定。

本版不修改官方客户端安装内容或签名，不修改 VM 的系统保护、磁盘或设备身份，也不会生成伪造 token。除明确选择的 ChatGPT 主进程外，不批量结束同名进程、子进程或系统认证服务。

## 这次怎么测试

1. 保存 Mac 中的工作并正常关机，用 TrollStore 覆盖安装 **0.4 Test 10 / 4011**，保留 Henge 数据和现有 Mac。
2. 启动原来的 Mac，把 **终端**输入行聚焦并切换到 **ABC / U.S.** 输入布局。在 **ⓘ → Details → Sharing** 点 **Type Install / Repair Command**，等命令输入完整后回到终端按回车。本次更新助手一次；回连应显示 **Mac helper 10 · Connected**。
3. 打开 **ChatGPT authentication · Test10**，先使用 **iPad DeviceCheck token**。保存 ChatGPT 中未发送的输入；针对这次反复退出超时的情况，可直接选择 **Force quit ChatGPT and retry**。如果希望先请求正常退出，则使用正常退出并启动按钮；超时后再选择强制退出重试。
4. 保持 Henge 在前台，等待界面的实际结果。只有显示 **Adapter ready**，才说明本次适配器接入已经得到确认。随后在 Mac 的 Chat 中发送测试消息；进程打开、宿主支持 DeviceCheck、取得非空 token、服务端接受 token 是不同结果。

不需要重建 Mac，也不需要先手动关窗口来模拟退出。只更新 iPad 端而仍运行 Helper 9，不能使用这次新增的强制退出能力。

## 自动诊断

**文件 → 我的 iPad → Henge → HengeDiagnostics → Latest-Henge-diagnostics.txt**

继续只提供这一个自动报告即可。它记录本次请求的模式、退出方式、固定阶段、PID、数字错误和耗时；不保存令牌、签名内容、Cookie 或对话，也不自动上传。

如果仍显示 `unknown error`，报告将区分尚未退出、退出后出现新进程、未观察到适配器加载、适配器接入失败、实际宿主认证请求失败等位置。没有请求回执时，不会把错误归给 Apple；没有握手时，不会声称适配器已经生效。

## 验证范围

macOS CI 使用自有的临时签名应用，验证超过 8 秒但在 30 秒内的正常退出、明确选择的强制退出、默认流程不强退、进程身份核对、授权撤销、重复请求和实际适配器握手。队列、HTTP 协议、助手安装与回连、iOS 编译、签名和安装包校验仍是发布前检查。

这些测试使用合成认证后端，不使用真实 Apple 账号，也不验证 OpenAI 服务端接受。最终仍以这台 iPad 和现有 Mac 虚拟机中实际能发送消息、收到回复为准。

Apple 的 [正常退出接口](https://developer.apple.com/documentation/appkit/nsrunningapplication/terminate()) 和 [强制退出接口](https://developer.apple.com/documentation/appkit/nsrunningapplication/forceterminate()) 都可能在应用实际结束前返回，因此本版在发出请求后继续核对进程。DeviceCheck 的功能和服务端验证边界见 [Apple 官方说明](https://developer.apple.com/documentation/devicecheck)。
