# Henge 0.4 Test 4.1（4005）

面向 iPadOS 17 / TrollStore 的测试包。本版处理 Mac 助手安装失败仍显示成功、连接状态误报，以及反复运行期间的资源压力；继续沿用 Test 3 的自动合并报告。

## 本版变化

- 包含 Test 4 的全部修复。Test 4.1 新增即时状态日志：每条已接收的安装回执，以及助手首次连接、进程变化和启动阶段变化，立即写入宿主原生日志并刷新 stdio 缓冲；不必等下一次周期采样。普通重复心跳不刷日志。

- 助手安装逐步检查下载、压缩内容、代码签名、版本和连接。先验证新文件，再替换旧版本；保留旧文件备份并在启动失败时回退，不再无条件显示“Henge is set up”。
- 助手使用独立的健康连接，在初始化剪贴板前报告启动状态。安装结果、启动阶段和最近连接分别记录，避免把“没有近期连接”解释为“没有安装”。
- Sharing 面板改用统一的 **Type Install / Repair Command**；下方显示连接状态与已知安装结果。只有接收到对应运行进程的连接确认，才报告安装成功。
- 新增可关闭的 **Reduced load** 设置：默认在最多 8GB 内存的 iPad 上启用，实际代码缓存限制为 **512MB**、显示刷新率限制为 **30Hz**。保留原有性能设置，不更改客体内存、CPU 数量或虚拟机磁盘。配置在 Henge 启动时确定，切换后需要保存 Mac 工作、正常关机并重开 Henge。
- 助手连接时先完成握手，自动 Chat 摘要采集仍按两分钟间隔安排；在严重热状态或最近收到内存警告时暂停新的自动采集。手动采集仍可用，既有摘要继续保留。
- 助手健康、安装结果和实际资源配置自动写入同一份诊断报告，无需挑选多个日志文件。

## 更新与测试

1. 保存 macOS 中的工作并正常关机，用 TrollStore 更新 Henge，核对 **0.4 Test 4.1 / 4005**。保留已有 Mac，无需重新创建或导入磁盘。
2. 启动原来的 Mac，在 macOS 中打开“终端”并点入输入区，键盘布局切换到 **ABC / U.S.**。
3. 打开 Henge 顶部 **ⓘ → Details → Sharing**，点 **Type Install / Repair Command**。回到终端，等整条命令输入完成后按一次回车，再等待安装结果。此按钮只输入命令，不会替用户提交回车。本版需更新一次 Mac 助手。
4. 查看 Sharing 的连接和安装状态；若安装失败，失败分类会自动保存在报告里，不必反复卸载助手或重建 Mac。
5. 在 Mac 中再试一次 Chat。如果问题仍在，Henge 会继续保存统一报告；也可点 **Collect Chat diagnostics**，再分享报告。

报告位置：**文件 → 我的 iPad → Henge → HengeDiagnostics → Latest-Henge-diagnostics.txt**。运行中的顶部详情面板也有分享和保存到文件入口。无需为了导出报告关闭 Mac。自动报告保留当前及上一轮日志，并归档最近 8 次 Henge 启动；系统终止前未写入磁盘的内容无法恢复；刷新 stdio 不等同于强制磁盘同步。

## 当前证据与限制

Test 3 实机报告确认多轮运行出现内存警告，但没有匹配的系统终止原因或异常栈。降低代码缓存和刷新率是可逆的缓解试验，不是已证明的 Jetsam 修复。动画会更不流畅，较小的代码缓存可能增加重新翻译的次数。

本版不把宿主的 DeviceCheck 能力当作 macOS 客体获得令牌的证据。已观察到的客体 `devicecheck_unsupported_device` 仍未有经验证的修复；不能将本包宣称为原生 Chat 已恢复。网页入口仍是替代入口，不等同于原生认证修复。

安装与连接检查只记录固定状态和错误分类。诊断不自动上传，不读取对话数据库、Cookie、令牌或钥匙串，也不在报告中保存安装命令的原始输出。

发布包须通过编译、协议与安装失败路径测试、签名和包内版本/提交校验。这些检查不能代替 iPad 实机上对助手、虚拟机稳定性和 Chat 的验证。
